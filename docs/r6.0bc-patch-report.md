# R6.0bc Patch Report — DittoSeller, Product Images, Assigned Stock Bugfix

**Date:** 2026-06-01  
**Scope:** R6.0bc patch only — no R6.0e fulfillment, activation hardening, OTA, or checkout serial assignment.

---

## 1. Root cause — Mis DittoBots stock invisible

**Symptom:** SuperAdmin assigns units successfully; vendor sees empty Stock tab.

**Cause:** `listUnitsForVendor()` uses the user JWT Supabase client. RLS on `ditto_bot_inventory_unit` only allowed:

- owner reads (`owner_user_id = auth.uid()`)
- pre-activation lookup
- activation/update own settings

There was **no SELECT policy** for regional vendors on `assigned_vendor_id` / `seller_vendor_id`.

Assignment writes via **service role** (admin client) succeeded; vendor reads were silently denied by RLS.

**Fix:** Migration `20260607130000_r60bc_patch_ditto_seller_rls.sql`:

- Column `store.can_sell_ditto_bots` (DittoSeller capability)
- Policy `ditto_bot_select_assigned_vendor` — authenticated vendor with `can_sell_ditto_bots` may SELECT units where `(assigned_vendor_id OR seller_vendor_id) = auth.uid()` and status in assigned lifecycle states

**Note:** In this codebase `store.id = auth.uid()` for vendor stores, so `assigned_vendor_id` correctly matches the logged-in vendor.

## 2. DittoSeller capability

| Layer | Implementation |
|-------|----------------|
| Data | `store.can_sell_ditto_bots boolean DEFAULT false` |
| Domain | `ditto-seller.policy.ts` — `assertDittoSeller`, `assertDittoSellerAssignmentTarget` |
| Admin action | `setVendorDittoSellerAction` (SuperAdmin only, audited) |
| Assignment | Only vendors with `can_sell_ditto_bots = true` in destination selector |
| Assignment UI | Toggle per vendor in Admin → DittoBots → Asignación |
| Vendor sidebar | `Mis DittoBots` shown only when `vendorHasDittoSellerAccess()` |
| Route guard | `/dashboard-vendor/dittobots` redirects to dashboard if not DittoSeller |

**Seed:** `dittobot-resistencia`, `dittobot-corrientes`, `dittobot-formosa` → `can_sell_ditto_bots = true`. Common vendors remain `false`.

## 3. Product images (DittoBot CRUD)

Reuses existing listing image model — **no parallel DittoBot image system**:

- Primary: `listing.characteristics.image` → `publication.attributes_json.image`
- Gallery: `listing.characteristics.images[]` → synced via existing `sync_listing_to_publication` trigger
- Variant: `listing_variant.attributes_json` updated on product save

**UI:** `DittoBotProductImagesEditor` in Admin → DittoBots → Productos (upload to `store-assets` bucket under `{officialVendorId}/ditto-products/`).

**Validation:** Primary image required on create; merge with existing on partial update.

Discovery/feed reads `attributes_json.image` — no DittoBot-specific discovery code added.

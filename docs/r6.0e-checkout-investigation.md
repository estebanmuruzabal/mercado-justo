# R6.0e — Checkout "Variante no encontrada" (investigación + fix)

**Date:** 2026-06-01

## Root cause

Discovery (publication mode) exposes `CommercialSnapshot.variantId` as **`offer_variant.id`**, while checkout and DB FKs (`cart_line.variant_id`, `order_item.variant_id`) require **`listing_variant.id`**.

DittoBot products **do** create a default `listing_variant` on product insert; the failure was an ID boundary mismatch, not missing variants.

## Fix applied

| Layer | Change |
|-------|--------|
| Offer mapper | `mapOfferVariantsToCommercialSnapshot` → `variantId = legacyVariantId ?? id` |
| Checkout resolver | `resolveCheckoutVariants` — listing lookup + offer→legacy fallback |
| Checkout action | Resolve variants + DittoBot stock gate **before** order insert |
| DittoBot stock | `validateDittoBotCheckoutStock` using `countDittoBotPublicStockByProductIds` (assigned only) |
